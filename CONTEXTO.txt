PATRON DE ARQUITECTURA QUE USA EL PROFE (a replicar):
  - Un componente = una responsabilidad. Funciones que empiezan con minuscula

  - El componente PADRE (ModuloRegistros) es el UNICO que tiene el estado de la
    lista de registros. Los hijos son "presentacionales": reciben datos por
    props y avisan cambios invocando funciones que tambien llegan por props.
  - Regla: "si un componente necesita saber de mas de un padre, subilo".
  - Los componentes hijos usan SU PROPIO useState para lo que es interno
    (lo que el usuario esta escribiendo en un input).
  - MUI Material para toda la UI. Iconos de @mui/icons-material.

REGLA DE ORO DE FLUJO DE DATOS:
  El hijo NUNCA modifica el estado del padre directamente. El hijo llama a una
  funcion que el padre le paso (onAgregar, onEliminar, onActualizar, onCancelar).
  El padre es el dueno del estado. Esta es la arquitectura "unidirectional".

import { useState } from 'react';
import Container from '@mui/material/Container';
import Header from './Header';
import Footer from './Footer';
import FormularioRegistro from './FormularioRegistro';
import TablaRegistros from './TablaRegistros';


function ModuloRegistros() {
  const [registros, setRegistros] = useState([]);

  const agregarRegistro = (nuevoRegistro) => {
    setRegistros((registrosPrevios) => [...registrosPrevios, nuevoRegistro]);
  };

  const eliminarRegistro = (idAEliminar) => {
    setRegistros((registrosPrevios) =>
      registrosPrevios.filter((registro) => registro.id !== idAEliminar)
    );
  };

  return (
    <>
      <Header titulo="Modulo de invalidos" totalRegistros={registros.length} />
      <Container maxWidth="md">
        <FormularioRegistro onAgregar={agregarRegistro} />
        <TablaRegistros registros={registros} onEliminar={eliminarRegistro} />
      </Container>
      <Footer />
    </>
  );
}

export default ModuloRegistros;

===== src/components/FormularioRegistro.jsx =====
import { useState } from 'react';
import Paper from '@mui/material/Paper';
import Box from '@mui/material/Box';
import TextField from '@mui/material/TextField';
import Button from '@mui/material/Button';
import Typography from '@mui/material/Typography';
import Alert from '@mui/material/Alert';


function FormularioRegistro({ onAgregar }) {
  const [nombre, setNombre] = useState('');
  const [email, setEmail] = useState('');
  const [edad, setEdad] = useState('');
  const [error, setError] = useState('');

  const limpiarFormulario = () => {
    setNombre('');
    setEmail('');
    setEdad('');
  };

  const validarCampos = () => {

    const campos = [
      { valor: nombre, etiqueta: 'Nombre' },
      { valor: email, etiqueta: 'Email' },
      { valor: edad, etiqueta: 'Edad' },
    ];

    let mensaje = '';
    campos.forEach((campo) => {
      if (!campo.valor.trim()) {
        mensaje = `El campo "${campo.etiqueta}" es obligatorio`;
      }
    });

    return mensaje;
  };

  const manejarEnvio = (evento) => {
    evento.preventDefault();

    const mensajeError = validarCampos();
    if (mensajeError) {
      setError(mensajeError);
      return;
    }

    const nuevoRegistro = {
      id: `reg-${Date.now()}`,
      nombre,
      email,
      edad,
    };

    onAgregar(nuevoRegistro);
    setError('');
    limpiarFormulario();
  };

  return (
    <Paper sx={{ p: 3, mb: 3 }} elevation={2}>
      <Typography variant="h6" sx={{ mb: 2 }}>
        Nuevo Invalido
      </Typography>

      {error && (
        <Alert severity="error" sx={{ mb: 2 }}>
          {error}
        </Alert>
      )}

      <Box
        component="form"
        onSubmit={manejarEnvio}
        sx={{ display: 'flex', flexWrap: 'wrap', gap: 2, alignItems: 'center' }}
      >
        <TextField
          label="Nombre"
          value={nombre}
          onChange={(e) => setNombre(e.target.value)}
          size="small"
        />
        <TextField
          label="Email"
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          size="small"
        />
        <TextField
          label="Edad"
          type="number"
          value={edad}
          onChange={(e) => setEdad(e.target.value)}
          size="small"
          sx={{ width: 100 }}
        />
        <Button type="submit" variant="contained">
          Agregar
        </Button>
      </Box>
    </Paper>
  );
}

export default FormularioRegistro;

import Paper from '@mui/material/Paper';
import Table from '@mui/material/Table';
import TableBody from '@mui/material/TableBody';
import TableCell from '@mui/material/TableCell';
import TableContainer from '@mui/material/TableContainer';
import TableHead from '@mui/material/TableHead';
import TableRow from '@mui/material/TableRow';
import IconButton from '@mui/material/IconButton';
import Typography from '@mui/material/Typography';
import DeleteIcon from '@mui/icons-material/Delete';

function TablaRegistros({ registros, onEliminar }) {

  const filas = [];
  registros.forEach((registro, indice) => {
    filas.push(
      <TableRow key={registro.id}>
        <TableCell>{indice + 1}</TableCell>
        <TableCell>{registro.nombre}</TableCell>
        <TableCell>{registro.email}</TableCell>
        <TableCell>{registro.edad}</TableCell>
        <TableCell align="right">
          <IconButton
            size="small"
            color="error"
            onClick={() => onEliminar(registro.id)}
            aria-label={`Eliminar registro de ${registro.nombre}`}
          >
            <DeleteIcon fontSize="small" />
          </IconButton>
        </TableCell>
      </TableRow>
    );
  });

  return (
    <TableContainer component={Paper} elevation={2}>
      <Table size="small">
        <TableHead>
          <TableRow>
            <TableCell>#</TableCell>
            <TableCell>Nombre</TableCell>
            <TableCell>Email</TableCell>
            <TableCell>Edad</TableCell>
            <TableCell align="right">Acciones</TableCell>
          </TableRow>
        </TableHead>
        <TableBody>
          {filas.length > 0 ? (
            filas
          ) : (
            <TableRow>
              <TableCell colSpan={5}>
                <Typography variant="body2" color="text.secondary" align="center">
                  Aun no hay registros
                </Typography>
              </TableCell>
            </TableRow>
          )}
        </TableBody>
      </Table>
    </TableContainer>
  );
}

function FormularioEdicion({ registro, onActualizar, onCancelar }) {

    const [edad, setEdad] = useState('');
    const [idEditado, setIdEditado] = useState(registro.id);

    if(registro.id !== idEditado){
        setIdEditado(registro.id);
        setNombre(registro.nombre);
        setEmail(registro.email);
        setEdad(registro.edad);

    const validarCampos = () => {

        const campos = [
            { valor: nombre, etiqueta: 'Nombre' },
            { valor: email, etiqueta: 'Email' },

            if (!campo.valor.trim()) {

 8. DECISIONES TECNICAS Y APRENDIZAJES (bitacora)
--------------------------------------------------------------------------------
1) PATRON: useState + useEffect para precargar props
   El componente recibe `registro` y debe mostrar sus datos en los inputs.
   Con solo useState('') los campos quedan vacios porque React solo usa el valor
   inicial en el PRIMER render. Si el usuario edita un registro y despues
   pulsa el lapiz de OTRO, React reutiliza el componente (misma posicion en el
   arbol) y los campos conservan los datos del anterior -> BUG CLASICO.
   Se resuelve sincronizando estado <-> props con useEffect y dependencia [registro].
   El array de dependencias [registro] NO se debe borrar: es lo que le dice a
   React "vuelve a ejecutar esto solo si registro cambio".

2) PATRON DERIVADO (avanzado, opcional): "ajustar estado cuando cambia una prop"
   Documentado por React. Evita el render extra (avisa el linter
   react/set-state-in-effect, warning de Performance, NO un error).
   Se implementa con un estado "sombra" (idEditado) que compara la identidad de
   la prop, y ajusta los valores en el cuerpo del render.
   REQUIERE inicializar los useState con el valor de la prop (no con '').
   DECISION PENDIENTE: cual usar. Recomendacion: useEffect (simple y estandar).

3) SPREAD DE OBJETOS: por que es obligatorio en manejarEnvio
   El `id` (reg-${Date.now()}) se creo al agregar el registro y vive en el
   objeto. Si al editar construimos { nombre, email, edad } SIN el spread,
   el id se PIERDE. Consecuencias: el key de React queda undefined, el boton
   eliminar llama onEliminar(undefined) y NO borra nunca. Ademas se perderia
   cualquier otro campo futuro.
   Patron correcto:
       const registroActualizado = { ...registro, nombre, email, edad };
   (El spread = "copiar todo lo anterior y encima pisar estos campos".)

4) useEffect ES CONDICIONAL EN ESTE PROYECTO
   a) useEffect(() => { setX(prop) }, [prop])  -> SI (sincronizar estado con props)
   b) useEffect(() => { fetch(...) }, [])     -> SI ( APIs externas, timers,
      suscripciones, event listeners). NO paraDerived state (useMemo), timers
      de cuenta regresiva simples, ni props que solo cambian de color.

5) ERROR #1 DEL ALUMNO (aprendido): nombre de componente en minuscula
   `function formularioEdicion()` -> React lo toma como etiqueta HTML y no
   renderiza nada. Los componentes SIEMPRE en mayuscula la inicial.

6) ERROR #2 (aprendido): estado declarado a medias
   Usar setError sin haber declarado [error, setError] -> ReferenceError.

7) ERROR #3 (aprendido): error de copy-paste en setters simetricos
   Escribir setNombre(registro.email) y setNombre(registro.edad) hace que el
   ULTIMO setNombre gane, dejando Nombre con la edad y Email/Edad vacios.
   REGLA: al copiar una linea cambiando una palabra, cambiar las DOS palabras
   simetricas (el valor Y el setter).

8) ERROR #4 (aprendido): {} en JSX no es texto
   variant={outlined} -> JS.   variant="outlined" -> texto.

9) ACERCION A props de MUI
   e.target.value SIEMPRE es string, aunque el input sea type="number".
   React no castea a numero. Por eso useState('') y setEdad('25') conviven bien,
   y .trim() es seguro sobre la edad.

10) BUG REAL DEL PROFE (buen apunte para la presentacion)
    En validarCampos, el forEach SOBREESCRIBE `mensaje` en cada iteracion:
        let mensaje = '';
        campos.forEach((campo) => {
            if (!campo.valor.trim()) {
                mensaje = `El campo "${campo.etiqueta}" es obligatorio`;  // pisa
            }
        });
    Si faltan Nombre y Edad, solo se ve el error del ULTIMO campo vacio.
    Deberia ser: mensaje = mensaje || ...  (o accumulating, o break).
    Copiamos el comportamiento del profe por consistencia, pero vale
    mencionarlo en clase: demuestra que leimos el codigo a fondo.
